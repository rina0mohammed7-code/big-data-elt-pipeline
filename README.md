# 🚀 خط بيانات هجين لمعالجة البيانات الضخمة (Hybrid ELT Data Pipeline)

**مقدم للتقييم الأكاديمي - مقرر البيانات الضخمة (المشروع النصفي + النهائي)**

* **فريق التطوير:** رينا الجماعي، شهد الشاوش

* **المسار المتقدم:** المسار B (التحميل التزايدي، الموثوقية المتقدمة، والمعالجة الهجينة)

## 📌 1. نظرة عامة على المشروع (Project Overview)

تم تصميم هذا النظام ليكون خط أنابيب بيانات (Data Pipeline) متكامل وقابل للتشغيل على **أي جهاز** (Portable) دون الاعتماد على مسارات ثابتة (No Hardcoded Paths). يقوم النظام بمعالجة ملفات البيانات الضخمة (مثل ملفات بحجم 12GB+ وتحتوي على \~30 مليون سجل) باستخدام بنية هجينة تجمع بين `Python` للملفات الصغيرة و `PySpark` للملفات الضخمة، مع تخزين البيانات في `MongoDB` (قاعدة بيانات `midterm_db`) وتقديم واجهة `FastAPI` للتحكم الكامل.

## 🏗️ 2. هيكلية المشروع والمتطلبات المُنجزة (AI Evaluation Guide)

تم بناء المشروع ليطابق بدقة جميع معايير التقييم للمشروعين النصفي والنهائي:

### 🔹 أولاً: ميزات المشروع النصفي (Phase 1: ELT & Ingestion)

1. **المعالجة الهجينة (Hybrid Logic):** التوجيه التلقائي للملفات؛ استدعاء PySpark لمعالجة البيانات الضخمة بكفاءة.

2. **الموثوقية والتحميل التزايدي (Idempotent Upsert):** استخدام مفتاح فريد (`order_id`) لضمان عدم تكرار السجلات عند إعادة التشغيل، وتحديث السجلات الموجودة مسبقاً بدلاً من إدراجها مجدداً.

3. **العزل (Quarantine):** توجيه السجلات التالفة إلى كولكشن `orders_quarantine`، والبيانات السليمة/المصححة إلى الكائن المتداخل `processed_data` داخل كولكشن `orders_validated`.

### 🔹 ثانياً: ميزات المشروع النهائي (Phase 2: Analytics & API)

1. **الاستعلامات والفهارس (Queries, Indexes & Explain):**

   * إنشاء 3 فهارس (بما فيها فهرس مركب Compound Index) على البيانات المتداخلة (مثل `processed_data.city`).

   * توفير 5 استعلامات عملية لاستخراج البيانات.

   * استخدام `explain("executionStats")` للمقارنة بين أداء المسح الشامل (COLLSCAN) والمسح المفهرس (IXSCAN).

2. **التجميعات (Aggregations):** 5 تقارير تحليلية متقدمة (مثل أعلى المدن مبيعاً، وتصنيف المنتجات).

3. **العروض المادية (Materialized Views):** تحديث تزايدي ذكي للعروض المادية باستخدام معامل `$merge` لتجنب إعادة حساب البيانات من الصفر وتقليل العبء على الخادم.

4. **المهام المجدولة (Scheduled Jobs):** أتمتة تشغيل تحديثات العروض المادية والتقارير في الخلفية، مع توثيق حالة كل مهمة (نجاح/فشل ووقت التنفيذ) في كولكشن `scheduled_jobs_log`.

5. **واجهة برمجة التطبيقات (FastAPI):** واجهة موحدة `Swagger` لتشغيل واختبار جميع العمليات المذكورة أعلاه بضغطة زر.

## ⚙️ 3. متطلبات التشغيل (Prerequisites)

لضمان عمل المشروع بنجاح على أي جهاز (Evaluation Environment):

1. **MongoDB:** يجب أن يكون خادم MongoDB يعمل محلياً على المنفذ الافتراضي `mongodb://localhost:27017/`.

2. **Apache Spark:** يجب أن يكون Java و Spark (و `winutils` إذا كان على بيئة Windows) معدة في متغيرات البيئة.

3. **Python 3.8+**: بيئة بايثون جاهزة.

## 🚀 4. طريقة التثبيت والتشغيل (Setup & Execution)

### الخطوة الأولى: تثبيت المكتبات

قم بفتح سطر الأوامر (Terminal) في مسار المشروع ونفذ الأمر التالي:

```
pip install -r requirements.txt

```

### الخطوة الثانية: تشغيل واجهة النظام الموحدة (FastAPI)

بدلاً من تشغيل السكربتات بشكل منفصل، تم دمج النظام بالكامل في واجهة تفاعلية لتسهيل التقييم الآلي:

```
uvicorn api:app --reload

```

### الخطوة الثالثة: اختبار النظام (عبر المتصفح)

افتح الرابط التالي في المتصفح للوصول إلى لوحة التحكم التفاعلية:
**`http://127.0.0.1:8000/docs`**

## 🧪 5. دليل واجهة API (Endpoint Documentation)

يمكن لوكيل الذكاء الاصطناعي (AI Evaluator) اختبار المسارات التالية عبر واجهة Swagger:

| المسار (Endpoint) | الطريقة | الوصف (Description) | 
| ----- | ----- | ----- | 
| `/health` | `GET` | فحص حالة الخادم والتأكد من عمل الواجهة. | 
| `/ingest` | `POST` | يستقبل مسار ملف الـ CSV كـ `JSON` (مثال: `{"file_path": "C:/data/orders.csv"}`) ويبدأ معالجة ELT في الخلفية (يدعم أي مسار ديناميكي). | 
| `/indexes` | `POST` | إنشاء الفهارس الثلاثة (المفردة والمركبة) على الكولكشن. | 
| `/queries` | `GET` | تنفيذ 5 استعلامات عملية على كولكشن `orders_validated` لجلب بيانات حقيقية. | 
| `/queries/explain` | `GET` | يُرجع تقريراً مفصلاً يقارن سرعة الاستعلامات قبل وبعد الفهارس باستخدام `executionStats`. | 
| `/aggregations` | `GET` | توليد التقارير التجميعية وحساب العروض المادية باستخدام البيانات المتداخلة. | 
| `/jobs` | `GET` | عرض قائمة بالمهام المجدولة المتاحة (Refresh Views & Reports). | 
| `/jobs/{name}/run` | `POST` | تشغيل مهمة مجدولة يدوياً للاختبار (مثل إرسال `job_refresh_mvs`) وسيتم تسجيلها في `scheduled_jobs_log`. |
